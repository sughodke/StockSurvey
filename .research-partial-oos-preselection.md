# Per-regime universe pre-selection as a rescue lever for `partial-OOS` rows

**Date:** 2026-05-25
**Status:** research-only investigation, no code changes.
**One-line answer:** No `partial-OOS` row in the current leaderboard has a failure mode where regime-conditioned universe pre-selection is the binding constraint. The lever is already substantially tested (3 separate prior arcs: macro→universe oracle, dca-basket-Optuna, dca-vol-ensemble Optuna) and is `confirmed-null` at the candidate-universe granularity the workspace has. **Recommendation: deprioritize this lever; rerank toward the open vol-v3 OOS-crisis question and the open meta-allocator `vol_v3-excluded` follow-up.**

## 1. Reaffirming the prior macro→universe-selection null

`.research-per-regime-universe-oracle.md` (2026-05-23) established that even the *in-sample* oracle ("which of 19 curated universes wins each regime, knowing the regime boundaries perfectly") produces winner-distributions at **94% of maximum entropy in the modal mid-VIX class** (27/45 regimes). Across 10 mid-VIX regimes flagged as `dca_winner_4etf`-original, every regime picked a different in-sample winning universe. The 2026-05-23 meta-allocator row (`b3 inverse-arc-vol`) reaffirmed the causal side: of five regime-forecasting candidates (Markov+Laplace, turbulence-overlay, meta-labeling, CUSUM, combo), **all five were reversed-OOS** against the inverse-vol baseline at 95% CI. The lever has been tested causally (meta-allocator), oracularly (per-regime universe oracle), and via direct universe-Optuna on the deployed basket (the dca-basket-Optuna row).

**What that null does NOT falsify:**

- **Micro-universe filters** — e.g. "rotate WITHIN the top-200 OI options names by a feature gate" (vol v3 already does this).
- **Non-VIX regime axes** — credit_baa, term-slope, m2_yoy, dispersion, breadth. The macro-regime-diagnostic row showed 5/6 macro features are directionally consistent with alpha at n=17; the oracle brief specifically picked VIX as the regime axis and didn't sweep these.
- **Short prediction horizons** — the oracle uses ≥21-TD regimes and arc-Sharpe-defined regime boundaries; per-rebal universe shifts at 5-20 day horizon are technically a different lever.
- **Non-equity universe spaces** — the prior tests all use baskets of ETFs or stocks. A universe defined over (date, options-contract) cells or (date, pair) cells is structurally different from "which 13 ETFs."

These three falsification-survivors are exactly where the live `partial-OOS` rows sit. The question is whether any of them actually changes the verdict.

- **Test design:**
  - **Hypothesis:** the canonical-13 basket is regime-suboptimal in a measurable way; a 2-3 regime conditional basket (e.g., low-VIX: equity-tilt; high-VIX: defensives) yields Δ deflated-t > +1.0 vs canonical.

  - **Validation:** strict walk-forward — at each rebal date t, the regime label uses only data ≤ t; basket choice for the next 60-80 trading days uses only data ≤ t. Train 2005-2018 / val 2019-2025.

- **Honest pre-reg:** if you write this, the expected verdict is `partial-OOS` or `confirmed-null`. The mechanism is real (regime-conditioning is the textbook play, see Asness/AQR style timing), but the empirical result on the workspace's 22-ETF universe is bounded by the macro-oracle null. **The strong case for running it anyway is methodological completeness** — closing the per-regime universe lever with a direct, falsifiable test rather than inference from oracle nulls.

## 4. Methodology gotchas

- **Survivorship trap.** An in-sample optimal universe per regime IS fitted on winners. The per-regime-universe-oracle brief documented this explicitly (25-30 TD regimes routinely pick single-asset universes with Sharpes >+4 due to window-fitting). Any walk-forward test must use **only data ≤ t** to define the regime label, the universe membership filter, AND the regime-to-universe mapping. The dca-basket-Optuna's strict train 2005-2018 / val 2019-2025 split is the right template.
- **Regime-label leakage.** "Regime" features built from realized arc-Sharpe (e.g. `regimes-since-2005.json` at L=252) are *post-hoc* labels — they look at the *outcomes* of the strategies whose universe you're selecting. Don't use them for causal selection. Macro features (VIX, credit, slope) computed point-in-time are the only valid regime axes.
- **Look-ahead in feature construction.** DoltHub's `hv_current[t+4w]` autocorrelation-leak (caught in vol-v3-dolthub-oos, 2026-05-14) is the canonical example: a "forward feature" must use *price returns*, not lagged HV snapshots.
- **Selection multiplicity.** A universe-Optuna search at 3,600 combinations and ~5 walk-forward windows is at the noise floor; the dca-basket-Optuna landed at deflated-t +0.42 / Δ deflated-t +0.016 specifically because DSR with `n_trials=200` punishes selection. Any per-regime version multiplies the search space and worsens DSR — pre-register the bar at Δ deflated-t **using the post-selection-penalty t, not the raw t**.
- **The Sullivan-Timmermann-White trap.** The vol-borrow Phase A → Phase B sequence is the workspace's cleanest STW-trap object lesson: in-sample +3.80 Sharpe on 11 fired rebals, OOS confirmation kills the directional finding entirely. **Any per-regime universe pre-selection result with n_fired < 30 must be treated as a Phase-A hypothesis for OOS, not a result.**
- **Per-regime sample size.** With 45 regimes (2026-05-23 brief) split across 7 winning families, the modal class (mid-VIX, n=27) has H/Hmax = 0.94. The non-modal classes have n ≤ 13. **A per-regime rule trained on n ≤ 13 samples cannot clear LW-CI at 95%** — this is the dispositive sample-size constraint and the reason no candidate above rates HIGH.

## 5. Final recommendation

**Deprioritize the per-regime universe pre-selection lever.** The three highest-EV candidates above each top out at probability MEDIUM and expected delta below the workspace's locked deployment bars (Δ deflated-t +1.0, LW-CI excludes 0). The macro→universe oracle is `confirmed-null` at 94% of max entropy in the modal regime class; the dca-basket-Optuna is `partial-OOS` within noise on the same axis; the meta-allocator showed all 5 regime-forecasting candidates `reversed-OOS` vs inverse-vol. The vol-v3 Phase A→B pair shows what happens when an in-sample regime-conditional finding meets OOS: it reverses.

**What to run instead:** the two open follow-ups already pre-registered are higher-EV than any per-regime universe candidate proposed here.

1. **B3 inverse-arc-vol with vol_v3 excluded** (the 2026-05-23 meta-allocator finding's own recommended next-test) — directly tests whether the +0.367 ΔSR vs 1/N is panel-structural or vol_v3-specific. ~0.5 pd, no Modal.
2. **vol-v3 deployment infrastructure + crisis falsification test** — `ss-vol live` + IBKR/Tradier options broker, ~12 h wall. Closes the deployable arc the workspace already has; the binding question for vol-v3 is "does the gate still fire correctly in the next crisis?", not "is there a better sub-universe?"

If a per-regime universe Optuna *is* run — for methodological completeness rather than EV — make it candidate **#1 (regime-conditional DCA basket)**, because it (a) has the cleanest test design, (b) extends an already-locked pre-reg (`TODO/dca-basket-optuna`), (c) carries a low blast radius (the verdict is almost certainly `partial-OOS within noise` and the canonical DCA basket stays deployed), and (d) the resulting null cleanly closes the lever for future agents who would otherwise propose it again.

Be explicit in the pre-reg's "expected outcome" section: **the steel-man case for per-regime DCA is the Asness/AQR style-timing literature, which finds modest (~+0.1-0.3 Sharpe) lifts on conditional sector/factor rotation in equity-only data.** This workspace's universe (13 ETFs, 20-year span, post-cost) is structurally smaller and more diversified, so the literature's lower bound applies but the upper bound is unlikely to clear +1.0 deflated-t. That's the honest pre-eval framing per CLAUDE.md's "believe in the test, not the outcome" rule — but in this case the genuine engagement with the literature still puts the expected post-eval verdict in the `partial-OOS within noise` band, which is the honest answer to give.
